## Rationale

**TASK-01 (AddXp return discards)** is the highest-value fix this iteration. Two separate code paths — achievement unlock and daily bonus — silently skip `LevelRewardTable` rewards on level-up. This is a P0 silent failure: the player levels up visually (HUD updates) but never receives coins or unlocks that the reward table promises. The fix is the same one-line pattern in two files, making it a natural single task. Because `TombakanOnboarding` already detects the daily-bonus level-up (Week 6 partial fix), wiring in `ApplyLevelReward` from the same location completes that fix.

**TASK-02 (GoalManager guard + false "-25!")** bundles two small fixes into one task. The GoalManager item is the only crash-risk bug in the report — `IndexOutOfRangeException` on every returning-player launch if `m_StepList` is populated in the Inspector. The false "-25!" fix is a single-line computation change that directly affects player trust: seeing a penalty notification when the score did not change is confusing and undermines the score-floor fix shipped in Week 1. Both are in the same area of onboarding/feedback code and together constitute one focused dev task.

**TASK-03 (ColourBlind "?" fix)** fixes a complete feature regression. With 8 starter species and only 4 exact hex values handled, the colour-blind shape overlay is broken for the majority of catalog play. This affects an accessibility feature that was explicitly designed and shipped; leaving it broken is not acceptable once a FishCatalog is wired. Nearest-colour or explicit mapping resolves it cleanly in one file.

**TASK-04 (toast timing)** addresses the most visible UX overlap in the result screen. A 0.4 s gap between level-up panel and achievement toast means players can never read the level-up message undistracted. Moving the toast to +3.5 s is a one-line change with immediate, player-visible impact during every game that ends in both a level-up and an achievement unlock — the most rewarding game sessions.

The artist slot is unused this iteration. All five reported bugs are logic or timing issues in `.cs` files. No prefab component values or material properties contribute to any of the ranked issues. Using the artist slot for cosmetic polish (e.g., fish squish animation) would be lower priority than the four code fixes above.
